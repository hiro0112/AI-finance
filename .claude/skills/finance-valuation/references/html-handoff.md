# 分析完了後のHTML連携

ユーザーから直接依頼された分析を完了し、成果物・検証結果を報告した後、HTML化を一度提案する。標準はBS・PLボックス図入りの経営分析ダッシュボード1HTMLで、financial-analysis-dashboardが担当する。既に「分析だけ」「HTML不要」と指定されていれば提案しない。

- **まだ選択されていない：** 完了報告の末尾で「経営分析ダッシュボード（BS・PLボックス図入り、1HTML）を作りますか？」と尋ね、回答を待つ。無回答を承諾と扱わず、HTML作成は開始しない。
- **出力を選択済み：** ダッシュボード（ボックス図入り）ならfinancial-analysis-dashboardを読む。ユーザーが図解だけを求めた場合はfinancial-statement-visualsを読む。入力モードをfinance-valuationとして作成・検証・引き渡しまで実行し、同じ許可を求めない。直前の提案に「はい／お願いします」と回答された場合は、ボックス図入りダッシュボード1HTMLが選択されたものとして扱う。
- **いいえ／今は不要：** 分析成果物を保持して終了。同じ分析について再提案しない。後から希望されたら再開する。
- **最初からHTMLまで依頼済み：** 確認を挟まず、分析確定後に指定されたHTML化へ続ける。種類が未確定の「HTMLも」だけなら出力範囲だけ確認する。
- **financial-statement-visualsまたはfinancial-analysis-dashboardからデータ準備のために呼ばれた場合：** データ・検証結果を呼出元へ返し、上記質問とHTMLスキルの再呼出しはしない。

HTMLを提案または実行する場合は、確認前（確認不要なら実行前）に、対象企業・表示期間・連結範囲・会計基準・通貨／単位・市場基準日、確定した原データ／Excel／出典の所在、指標の定義・式、欠損・未検証事項、出力先、外部取得制限を引き渡せる状態にする。ファイル成果物がある分析では当該分析の出力フォルダに `visuals-handoff.json`（既存なら別版）を保存し、これらの条件と既存ファイルの絶対パスを記録する。5区分の分析本文・課題・比較、セグメント表・解説、全体診断の所在も、[コメント引継ぎ仕様](analysis-commentary.md#成果物への反映と検証)に従って記録する。Wordの有無を引継ぎ条件にしない。既存データを重複転記する必要はない。会話内だけの小さな分析は値・定義・出典を会話から引き継いでよい。

出力選択後は入力の再選択を求めず、両スキル共通の変換手順で原明細・指標結果を共通データへ整理する。対象年度と既存の市場基準日を保持し、承諾を株価更新・追加調査の許可へ広げない。分析が単年なら単年を引き継ぎ、足りない三表・指標は理由付きで示す。HTML化への承諾だけで詳細5年分析を追加取得しない。変換は一度だけ行う。

選択されたスキルが利用できなければ所在を探索し、それでも利用できない工程の理由を伝える。利用できる依頼済み工程は完成させ、分析成果物と引継ぎ情報を渡す。利用可能なときは呼出例を提示するだけで終わらず、実際に最後まで作成する。
