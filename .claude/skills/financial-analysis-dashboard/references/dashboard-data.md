# ダッシュボードの分析データ

[共通データ契約](../../financial-statement-visuals/references/multi-year-data.md)を確定した後に適用する。共有JSONに以下の本文・指標を保持する。

## 分析コメントの受け渡し

元資料から引き継ぐのは財務数値・分析・根拠・判断条件。過去の催し、登壇、講義、進行台本などに固有の見出し・案内は、その用途が今回の成果物にも明示指定された場合だけ掲載する。指定がなければ分析上の意味を保って一般的な表現へ直し、進行用の案内は除く。数値・出典・対象期間・仮説・留保は維持する。

元レポートまたは `visuals-handoff.json` の `analysis_commentary_path` を読み、ダッシュボードを作る場合は共通JSONのトップレベルの配列 `analysis_commentary` に本文と参照を保持する。単独の図だけならこの配列は任意。Wordの新規作成は不要。各要素は `id, company_ids, period_ids, coverage_label, origin, category, assessment, evidence, background, issues, actions, kpis, book_refs, limitations` を基本とし、5区分の対応を `section`（PL / BS / CF / metrics / segments）、個社／比較を `commentary_type`（company / comparison）に記録する。全体総括はsection=summaryとして追加できる。`origin` に元分析からの継承／HTML化時の追加と元レポートの所在を記す。`company_ids` は企業ID配列、`period_ids` は企業IDをキーとする対象期ID配列の対応表にする。`background` では開示事実／仮説、`actions` では提案を区別する。`evidence` に数値の項目パス／セルと出典、`book_refs` に書名・章・PDFページを記す。比較コメントは両社の実際の対象期を保持する。

コメント配列を持たない旧JSONも入力として引き続き使用できる。ダッシュボード用の出力は上記のv2形式へ変換する。コメント不足なら提供データの範囲で補足し、根拠不足は判断保留とする。ダッシュボードでは各社×5区分、および2社の場合は比較×5区分を揃え、未入手・非該当も理由と必要資料を持つレコードにする。旧categoryからの変換対応をmapping.jsonに残す。検証スクリプトはコメント内容を検証しないため、数値と文章の整合・期間・出典・改善案とKPIの対応を別途確認する。各HTMLには必要なコメントも内包し、分析メモのローカルパスをfetchする仕組みにしない。

## セグメント表と本文の保持

ダッシュボードでは `segment_data_path` または既存Excel・JSON・レポートから表と解説を取り込む。共通JSONの企業レコードに `segments` を置き、開示状況・対象期間・売上と利益の定義・事業別の年度値・単位・出典・消去／全社調整・連結との照合結果を保持する。元の構造を使う場合もmapping.jsonで所在を特定する。未開示・未入手は状態と理由を保持し、0で埋めない。数表だけでは解説を代替しない。

本文の完全性は[management-analysis.md](management-analysis.md)で確認する。データ検証スクリプトはanalysis_commentary・segments・経営課題の内容を検証しない。収録一覧に各社／比較の5区分、元分析の重要論点、セグメント表・解説、全体診断、優先順位、出典・制約と、対応するHTML見出し／アンカー・不足理由を記録して照合する。

## 外部取得時の標準指標

finance-valuationを利用する場合はその詳細5年分析定義を優先する。未利用時の標準は以下。全項目を表示し、算出不可は理由付きN/A/N/Mにする。

| 分類 | 項目・定義 |
| --- | --- |
| 収益性 | 粗利益率、営業利益率、親会社純利益率＝対応利益/売上。ROE＝親会社純利益/平均親会社持分。ROA＝親会社純利益/平均総資産 |
| 成長性 | 売上・営業利益・親会社純利益の前年比とCAGR。5通期CAGRは4乗根。前年比の前年が0以下、CAGRの端点が0以下ならN/M |
| 安全性 | 自己資本比率＝親会社持分/総資産、流動比率＝流動資産/流動負債、有利子負債、ネットデット、ネットデット/EBITDA。有利子負債のリース範囲と控除現金範囲を明示。EBITDA＝営業利益＋対応D&A |
| 効率性 | 総資産回転率、DSO・DIO・DPO・CCC。[共通定義](../../finance-valuation/references/working-capital-analysis.md)を適用。単位・分母・平均方法・日数・近似・欠損理由を保持 |
| キャッシュ創出力 | 営業CF、設備投資（有形・無形取得支出の正数）、FCF＝営業CF−設備投資、営業CFマージン＝営業CF/売上 |
| 市場指標 | 株価、時価総額＝株価×対応株数、実績PER＝株価/直近公表通期の基本EPS、PBR＝株価/最新公表BPS |

平均残高の開始前年BS、初年度前年比の前年PL/CFは補助データとして取得。ROEの親会社持分が負・ゼロ・極小・符号反転する場合は解釈限界を説明し、意味を持たない倍率を優良指標として強調しない。分母0、適用不適切な業種、EBITDAが0以下などは機械計算しない。

市場は最新共通取引日の確定終値を標準とし、取得日時・取引所・通貨・EPS年度・BPS期末・株数時点を残す。EPS/BPSが0以下なら対応倍率はN/M。自己株式控除、親会社普通株主持分、分割・ADR・複数種類株式の単位を揃える。EPS用平均株数とBPS用期末株数を混同しない。過去市場指標の追加依頼では、当時公表済み情報か事後対応かを区別し、最新株価を5年のEPSに使い回さない。

生産性は共通定義に従い補足とする。DSO・DIO・DPO・CCCの値と定義情報は共有JSONの既存指標格納先へ保存し、mapping.jsonで所在を特定する。旧データにない指標は提供データ内で算出できる場合に追加計算と記録し、不足時は理由付きN/A。CCCの3要素と分析本文をHTMLに保持する。数値スクリプトの合格だけではCCCの算式や本文の正しさを保証しない。

## 全体診断の追加データ

任意の`integrated_analysis`に、会社別の年度別ROE3要素・ROA・ROIC（参考値ならその区分）、投下資本・NOPAT・税率と根拠、比較期間別の変化寄与と方式、会社別総括、施策の効果・条件・KPIを保持してよい。通常指標の定義は上書きしない。元データと同一の対象期間を示し、HTML内で独自の税率や計算方式へ変更しない。
