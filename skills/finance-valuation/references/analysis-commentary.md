# 書籍の考え方を使った各社分析・2社比較コメント

財務分析・決算比較のコメントを作るときに読む。指標の定義・計算は既存のfinancial-analysis.mdを維持し、本書の式や過去事例で上書きしない。単独指標だけの質問、数表のみの指定はその範囲を優先する。

## スキルに整理した判断基準を使う

[book-analysis-notes.md](book-analysis-notes.md)はスキル構築時に確認した考え方と出典の記録である。通常の分析では本ファイルに整理済みの判断基準を適用し、出典にはノートに保存した書籍ID・章・PDFページを使う。企業の実績の根拠は当該企業の開示資料、読み方の根拠はスキルに取り込んだ書籍の考え方、施策は分析者の提案として分ける。書籍がその2社を比較した、または提案を推奨したと誤記しない。

書籍原本の確認はスキルの構築・改訂時に限る。通常の分析・コメント補足・再生成・HTML化では書籍フォルダの探索、PDF閲覧、OCR、書籍の再提示依頼を行わない。原本へのアクセスを実行条件にせず、原本を今回読まないことを分析の未検証事項に数えない。新しい論点でも自動的に原本へ戻らず、企業開示と整理済みの判断基準で分析し、根拠不足なら判断保留とする。保存済みノートの再利用を今回の原本照合と報告せず、ノートにない論点・ページを特定の書籍へ帰属させない。

## PL・BS・CF・経営指標・セグメントから課題を導く

財務分析の本文は次の5区分を必須とし、下記6領域の評価を関連する区分へ織り込む。単独指標などの明示された範囲を優先する。各区分に「分析結果 → 数値根拠・推移 → 開示された背景／仮説 → 経営への影響 → 導かれる課題」を置く。未入手・非該当は理由と判断に必要な資料を記す。

- PL：売上から利益への構造、利益率・費用・一時損益の変化から、成長と採算の課題を導く。
- BS：資産構成、運転資本、現預金・金融資産、負債・自己資本から、資産効率・流動性・調達・資本配分の課題を導く。
- CF：営業・投資・財務CF、利益と営業CFの差、設備投資・FCFと資金使途から、利益の質・投資回収・資金持続性の課題を導く。
- 経営指標：成長性・収益性・安全性・効率性・資金創出力の水準と推移、ROIC・ROA・ROEとデュポン分解から、改善すべき要因を示す。市場指標を含む場合は時点・期待・リスクとの関係を説明する。
- セグメント：下記の売上・利益表と解説から、各事業の役割、採算・成長・集中と資源配分の課題を導く。

2社では各区分を比較単位とし、「A社の数値と分析／B社の数値と分析／差の背景・比較限界／A社の課題／B社の課題」を一緒に示す。各社別解説に加え、共通課題と固有課題を明記する。単なる2社分の数表や個社レポートの並置では完了しない。PLの利益、BSの資産・調達、CFの現金、セグメントの事業要因をつないで全体結論を出す。

## 出力の順序と必須欄

2社分析は「全体の結論 → 本質的な課題 → A社 → B社 → 2社比較 → 改善の優先順位 → 出典・判断限界」で構成する。単独社なら比較欄を省く。短い回答では欄を文章に統合し、企業別と比較の両方の結論・改善案・確認指標を残す。重要課題を優先し、不足領域と書籍参照は末尾に集約してよい。

全体の結論には [capital-efficiency-analysis.md](capital-efficiency-analysis.md) のROIC・ROA・ROEとデュポン分解から導く診断を含め、資本配分の選択肢・実行条件へつなぐ。

各社について以下の6領域を確認し、資料のある領域は最新期の水準と対象期間の推移をコメントする。不足領域は「判断保留＋必要資料」、金融など適用しない領域は理由と代替指標を示す。問題が見当たらなければ「確認範囲で顕著な問題なし」と書き、維持条件・監視点を示す。

| 領域 | 数字から読むこと | 課題・改善案につなぐ着眼点 |
| --- | --- | --- |
| 成長性 | 売上・営業利益・純利益の前年比／CAGR、セグメント推移 | 数量・価格・構成・為替・M&A・製品周期を開示の範囲で分ける。増収と利益・CF成長の不一致、成長投資の回収可能性 [B1a] |
| 収益性 | 粗利益率・営業利益率・純利益率の水準／変化 | 原価・販管費・製品構成・一時損益を検討。価格やコストの施策は数量・品質・将来の開発力への影響も考える [B1a] |
| 安全性 | 自己資本比率、流動性、ネットデット、返済期限、利払い余力、CFの安定性 | BSの資本の厚さと短期の支払能力を別々に評価。借入削減／還元継続の判断に必要なCFと債務条件を示す [B1c, B2a] |
| 効率性・資本収益性 | ROE・ROA、総資産回転率、ROIC（算出可能な場合） | ROEを純利益率×総資産回転率×財務レバレッジへ分解。平均残高・利益・持分の範囲をそろえる。事業の稼ぐ力と自己資本縮小の効果を分ける [B1b] |
| 資金創出力・利益の質 | 営業CF・FCF・設備投資、利益と営業CFの差、在庫・債権・債務、CCC | 非現金損益、運転資本、税金等の橋渡し。成長投資によるFCF減と恒常的な資金不足を区別。在庫圧縮・回収促進の副作用も示す [B2b, B2c] |
| 資本配分・持続性 | 現預金・金融資産、投資・配当・自社株買い・借入の関係、事業集中・循環 | 必要運転資金・投資機会・不況時の備えから保有現金を検討。投資、返済、還元の選択肢と条件を示す [B2d, B3] |

各コメントは次の要素を短い文章または表の列にする。

1. **特徴・評価**：何が強みで、何が課題か。
2. **数値根拠**：会社・対象期・値・変化幅・定義・出典／セル参照。率の差はポイントで書く。
3. **背景**：開示で確認した理由と、分析者の仮説を明示的に区別。
4. **課題・問題点**：何に影響し、どの条件で問題になるか。懸念だけなら条件付きのリスクと記す。
5. **改善案**：当該課題に対応する具体策、期待する作用、実行条件・副作用。
6. **確認KPI・追加資料**：施策後に何で改善を判定するか。必要な未開示データも示す。

重要な課題を優先順にまとめ、優先する理由を資金繰りへの影響、影響の大きさ、緊急性、確度から説明する。数値目標・期限・効果額は会社公表値と提案を区別し、根拠なく設定しない。既存施策を新規提案する場合は、現状と追加改善部分を分ける。

## 本質的な課題を抽出する

5区分（PL・BS・CF・経営指標・セグメント）で見つけた個別の課題は「症状」として扱う。それらを生み出している事業構造・収益モデル・資本配分の根本原因を「本質的な課題」として、各社2〜3件に絞る。

各件に次をそろえる。

1. **本質的な課題**：1文で言い切る。
2. **症状として現れている数値**：原則2区分以上から。会社・期間・値・定義・出典／セル参照。
3. **因果のつながり**：症状 → 直接の要因 → 根本原因。開示で確認した事実と分析者の推測を分ける。
4. **放置した場合の経営への影響**：利益・現金・資本効率・財務余力のどこに、どの条件で効くか。
5. **確かめる／覆す情報とKPI**：仮説が正しいか判定する資料・指標と、判断が変わる条件。
6. **対応の方向**：分析者の提案として、実行条件・副作用を添える。会社の公表施策と区別する。

「ROEが低い」「利益率が下がった」など指標の悪化そのものを本質的な課題と呼ばない。1つの指標だけから導かない。業界の一般論で終わらせず、当該企業の数値につなげる。資料で確かめられない根本原因は仮説と明記し、断定しない。2社の場合は共通する本質的な課題と各社固有の課題を分ける。改善の優先順位の各課題には、対応する本質的な課題を示す。

Excelの分析コメントシートと分析メモでは「全体の結論」の次に置き、引継ぎデータ（`analysis_commentary_path`）にも含める。

## セグメント売上・利益と解説を収録する

通常の財務分析・企業比較では、セグメント開示がある各社について、**Excelと引継ぎデータにセグメント売上・利益の表と解説を保持し、後続ダッシュボードの本文にも掲載する**。Wordを明示依頼された場合はWord本文にも掲載する。HTMLや依頼済みWordでは、連結数値の表や文章中の一部数値、Excelのセグメント表への参照だけでは代替しない。単独指標・数表のみなど明示された依頼範囲は優先する。

- 表は事業を行、対象期ごとの売上・利益・算出可能な利益率を列とする。比較年数は依頼した分析期間に合わせ、勝手に5年へ広げない。単年なら単年と明記する。組替後の比較値があれば採用し、セグメント変更で比較できない期は理由を示す。
- 売上が外部顧客売上か内部取引込みか、利益が営業利益・調整後利益・EBITDA等のどれかを見出し・注記で明示する。利益定義が不明なら営業利益と断定しない。利益率の分母をそろえ、定義が違う会社間の優劣は留保する。
- 消去・全社費用・調整と連結合計を、開示に応じて表または照合注記に載せる。連結との一致と丸め差を検算し、差の理由が不明なら未照合と記す。消去行の利益率は対象外。内部取引込み売上を連結外部売上で割った値を無注記の構成比にしない。
- 解説は、各主要事業の役割、売上と利益の伸びの違い、利益率の変化、連結の増減を支える／押し下げる事業、課題・資源配分への示唆を数値で説明する。会社が説明した増減理由と分析者の仮説・改善提案を分け、未開示の原因を断定しない。利益率だけで事業ROICや資本配分の優劣を決めない。
- 報告利益と一時損益等の調整後利益は並べ、加減算の根拠と利益段階を示す。調整後利益を恒常利益と断定しない。赤字からの変化は通常の成長率より損失増減額を使い、連結利益が赤字・極小なら通常の利益構成比はN/M等と理由を記す。
- 単一セグメント、利益未開示、資料未入手はその状態と分析限界を明記し、欠損をゼロや推計で埋めない。開示される売上だけでも掲載し、利益・利益率は未開示等とする。
- Excelと同じ確定データを使い、会社・対象期・単位・利益定義・出典ページを追えるようにする。ダッシュボードの表・解説とExcelの値・符号・増減率・率のポイント差を照合する。Wordを作る場合も同様に照合し、各成果物の表、数値の見切れ、日本語表示、印刷時の改ページを確認する。

## 2社比較は差の理由と会社別の改善につなぐ

比較表の列は「観点／A社の特徴・数値／B社の特徴・数値／差の背景・比較限界／各社の課題と改善方向」。原則として上記6領域をカバーし、比較不能な領域も理由を残す。各社の説明を並べるだけで終わらず、次を述べる。

- どの観点で差があり、その差が事業モデル・規模・事業周期・会計・資本政策の何から生じるか。根拠未確認の原因は仮説。
- 共通する課題と会社固有の課題。それぞれに対応する改善策と確認KPI。
- 相手から学べること、転用する条件、転用できない事業上の理由。劣る指標だけを理由に相手と同じ資本政策・利益率を目標にしない。

異業種・規模差のある比較でも特徴を説明できるが、総合順位を無理に付けない。期間・会計・通貨が異なるときは条件を明記し、原通貨額の単純な倍率比較を避け、比率・構成比・各社内の推移を併用する。業界ベンチマークが不要と指定されている場合は追加しない。

## 運転資本と資金繰りを結び付ける

[working-capital-analysis.md](working-capital-analysis.md)を適用し、DSO・DIO・DPO・CCC、資産の換金性と支払期限、負の持分の原因、営業CFと調達条件をつなぐ。各社分析・比較に、重要な悪化シナリオと判断の成立条件・不足情報を含める。既存の6領域は「標準5軸＋資本配分」の構成であり、生産性は補足とする。

## 誤読を防ぐ条件

- 高自己資本比率を無条件の優良評価、低自己資本比率を即危険としない。高ROE・EPS増加は利益成長と自社株買い等の分母効果を分ける。負・極小の持分で意味を失うROEはN/Mと理由を示す。当期末持分と分母に使う期首期末平均持分を区別し、期中の符号反転も確認する。
- FCF赤字だけで投資失敗とは判断しない。FCF定義、投資内容、回収見込み、調達余力を確認する。EBITDAを営業CFや返済に使える現金そのものとしない。
- 在庫増とCF悪化が同時でも因果は未確定。CF内訳や回転日数を確認し、期末在庫だけで在庫回転日数を捏造しない。
- ROICとWACCの定義・時点・事業リスクが対応するときだけ差を評価する。資本コスト未入手なら価値創造の判定は保留し、コメントのためだけにDCFを追加しない。
- 現金を全額余剰扱いしない。政策保有株を自由な現金と同一視せず、売却制約・税・価格変動を考える。還元や借入を増やせば企業価値が上がると断定しない。
- PER・PBRを掲載する場合は期待成長・資本収益性・リスクとの関係を解説し、倍率だけで割安・割高を断定しない。

## 短い記述例（架空値）

A社は売上が100から120へ20%伸びる一方、営業利益率は15%から10%へ5ポイント低下した（提供値から計算）。増収を利益へつなげることが課題である。製品構成や費用増が背景として考えられるが、内訳未入手のため仮説。製品別の採算を確認し、低採算取引の価格・調達条件の見直しを検討する。値上げによる数量減を同時に点検し、営業利益率・販売数量・営業CFで効果を確認する。成長と収益性を合わせて読む視点はB1aに基づき、施策は分析者の提案。

## 成果物への反映と検証

- Excelの分析コメントシートは維持し、「本質的な課題」「各社分析」「2社比較」「改善の優先順位」が読める欄を置く。後続ダッシュボードへ詳しい評価・課題・改善案を載せることを理由に、このシートのコメントを削除・移動しない。Wordは明示依頼時だけ作り、同じ結論と根拠を使う。別シートの数は固定しない。
- 手入力の文章は分析時点のスナップショット。数値を変更した場合、指標が再計算されても文章の再評価が必要と明示する。
- HTMLへ渡す際は、コメント本文・対象会社／期間・数値参照・書籍参照・仮説／提案・未確認事項を含む分析メモの絶対パスを `visuals-handoff.json` の `analysis_commentary_path` に記録する。既存の機械可読データにコメントが揃っていればそのパスを使い、Wordを機械可読のJSON・Markdownと偽って扱わない。`analysis_commentary_path` はPL・BS・CF・経営指標・セグメントの本文、各区分の課題、2社なら各区分の比較、全体診断、本質的な課題、優先順位、出典・制約を含むJSONまたはMarkdownの既存データ／補助メモを指す。Excelだけに本文がある場合は該当シートから抽出して照合する。セグメント数表の所在は `segment_data_path` に記録し、同じファイルなら同一パスを使う。セグメント開示なしの場合も状態と理由を渡す。`analysis_report_path` は実在するWordを明示依頼で作った場合または既存入力として使う場合だけ記録し、未作成なら省略する。補助メモは正式な別レポートの作成要求ではない。
- 数字・符号・率とポイント、各社欄と比較欄の整合、本質的な課題と症状の数値・優先順位の対応、改善策とKPIの対応、書籍と企業出典の区別を確認する。データ不足の解消を装っていないかを確認して引き渡す。
