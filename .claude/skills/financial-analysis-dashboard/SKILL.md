# 経営分析ダッシュボード

経営陣・幹部社員が数字を探索し、人間の判断へ進める分析HTMLを作る。標準成果物は、BS・PLボックス図を「要約の次」に収録した経営分析ダッシュボード1点。

用途を特定の催しや利用場面に固定しない。画面の見出し・説明・問いかけは一般的な経営分析の表現を標準とし、用途固有の案内はユーザーが今回の成果物に指定した場合だけ加える。

## 出力と入力を確定する

- ダッシュボードの依頼は本スキルで1HTML（BS・PLボックス図入り）。Excel・Wordを追加しない。
- 図解だけの依頼は [financial-statement-visuals](../financial-statement-visuals/SKILL.md) へ引き継ぐ。
- 財務図解と経営分析の両方を依頼された場合も、BS・PLボックス図を収録した経営分析ダッシュボード1HTMLにまとめる。親が共通データを確定する。既に依頼済みなら再確認しない。「HTMLも」だけで種類が未確定なら、ボックス図入りダッシュボード1HTMLでよいかだけ確認する。
- 企業・期間・範囲・出力先は会話から引き継ぐ。外部取得では直近公表済み5通期を標準とし、指定期間を優先。既存分析の再利用では単年・2期でもその期間を保持し、株価を含む更新・追加調査を無断で行わない。企業や入力の所在が不明な場合だけ確認する。

[共通データ契約](../financial-statement-visuals/references/multi-year-data.md)で入力経路とv2 JSONを確定し、[ダッシュボードの分析データ](references/dashboard-data.md)で本文・セグメント・指標を引き継ぐ。会計規約と数値検証スクリプトはfinancial-statement-visualsの共有資源を使う。参照のために図解スキル全体を実行する必要はない。データ取得・変換は親が一度だけ行い、確定データを再準備しない。

共有資源は同階層のfinancial-statement-visualsを参照する。所在が異なれば利用可能スキルから解決し、見つからなければデータ契約・数値検証工程の不足を報告する。ボックス図の描画仕様は[boxes.md](../financial-statement-visuals/references/boxes.md)を共用する。

## 探索型の分析本文を作る

[dashboard.md](references/dashboard.md) と [management-analysis.md](references/management-analysis.md) を読む。標準は基本3問程度の問い → 図表で探索 → 事実・仮説と判断条件 → 人間が判断する論点。結論先行・意思決定支援型は明示指定時に使う。「経営会議向け」だけで結論先行へ変更しない。

PL・BS・CF・経営指標・セグメントの5区分の分析結果と経営課題、2社なら区分ごとの比較と各社分析を必須収録する。5区分の課題を症状として束ねた「本質的な課題」（各社2〜3件）を[本質的な課題の抽出](../finance-valuation/references/analysis-commentary.md#本質的な課題を抽出する)に従って収録し、「経営課題と人間の判断」の先頭に置く。元分析にない場合は提供済みデータの範囲で抽出し、HTML化時の追加と明記する。分析本文の最後（「経営課題と人間の判断」の後、詳細三表・市場指標・出典などの資料の前）に、各社の「強み・弱み・課題・今後の戦略の方向性」のまとめを置き、2社なら並べて比較する。書き方は[dashboard.md](references/dashboard.md#強み弱み課題戦略の方向性のまとめ)に従う。セグメント表・解説、ROIC・ROA・ROEとデュポン分解による全体診断、資本配分の選択肢・条件・KPIを保持する。既存の主要数値・解説・比較・優先順位・出典・制約を引き継ぐ。Wordの作成・存在を前提にしない。

元分析の数値根拠・書籍参照・仮説・判断限界を保持し、コメント不足なら提供済みデータの範囲で補い、追加解釈を明示する。書籍原本は通常制作で開かず、元分析とスキル内の判断基準・出典メモを使う。未開示・未入手は理由付きで示す。

[経営指標5軸と資金繰りの共通判断基準](../finance-valuation/references/working-capital-analysis.md)を読み、総資産回転率・DSO・DIO・DPO・CCCを標準表示する。生産性は補足。元分析に不足があれば提供データ内で補い、未入手・非該当の理由を残す。指標の高低だけで安全性を決めず、換金性・期限・営業CF・調達条件と定性的な悪化シナリオを本文に反映する。共通参照が見つからなければ不足を報告し、旧来の任意指標扱いへ黙って戻さない。

## HTMLと他の成果物をつなぐ

[共通操作](../financial-statement-visuals/references/html-interaction.md)に従い、問いと最新年度の主要数値を入口に対象期間の推移を探索できるようにする。BS・PLボックス図は要約の次に置き、[boxes.md](../financial-statement-visuals/references/boxes.md)の共通縮尺・構成比切替・負の純資産や赤字の扱いを守る。ダッシュボードの年度選択に連動させ、元データ表（金額・構成比・出典）とストック／フローの注記を添える。冒頭の問いから関連する場合はボックス図へ導線を付ける。年度連動する値と固定期間の総括を区別し、市場基準日は独立表示する。

日本語、外部ライブラリ不要の単体HTMLを標準とし、原データ・本文・出典を内包する。ローカルJSONのfetchは前提にしない。ユーザーの参照画像・表示指定を優先する。ファイル名は `YYYY-MM-DD_企業名_経営分析ダッシュボード.html`。既存版は保持し、改訂は別版。自動コミット・公開はしない。

制作は原則親が担当し、ボックス図もダッシュボード内で親が描く。別のindex.htmlは追加しない。

## 検証と引き渡し

1. `python3 "{VISUALS_SKILL_ABSOLUTE_PATH}/scripts/validate_bundle.py" /absolute/path/financial-data.json` で全年度の構造・関係式を検査。原資料、全明細の網羅、指標計算、市場基準日は別途照合する。
2. [定性分析の受入確認](references/management-analysis.md#受入確認)で各社・比較の5区分、セグメント表・解説、全体診断、本質的な課題と優先順位の対応、課題・KPI、元分析の重要論点、問いから判断までの導線を照合する。数値検証だけで本文を合格にしない。
3. 許可されたブラウザで全企業・全年度・操作・リンク・小画面・印刷を確認。欠損・赤字・負の自己資本、非表示本文、NaN/Infinityを点検。実画面未確認は別途報告する。
4. 出力が経営分析1HTML（ボックス図入り）であることを確認する。ボックス図は全年度×金額／構成比でNaN・負の寸法・はみ出しがないこと、箱の高さが金額に比例すること（共通縮尺）、要約と同じ年度を表示することを確認する。
5. 成果物の絶対パス、操作、仮定・未検証事項を報告。SKIPは合格と区別する。依頼されていない追加工程を始めない。
